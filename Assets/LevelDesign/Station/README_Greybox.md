# Грейбокс станции — первая итерация

Проект: `D:\Pr\Atmosphere\Atmosphere`, ветка `Level1`, Unity 6000.3.27f1, URP. Используется уже установленный Newtonsoft JSON 3.2.2; новых пакетов нет.

## Запуск

1. Откройте проект Unity и сцену `Assets/LevelDesign/Station/Greybox/StationGreybox.unity`.
2. JSON уже находится в `Assets/LevelDesign/Station/station_layout_v4_story.json`. Его исходное содержимое сохранено без изменений. При замене используйте ту же схему: `polygon_xy` и `doors[].endpoints`, метры, XY плана → XZ Unity.
3. Для новой сцены: **Tools → Station → Create Test Scene**. Сохраните текущую безымянную сцену перед вызовом; новая сцена добавляется отдельно и получает уникальное имя.
4. Для повторной генерации в активной сцене: **Tools → Station → Generate Greybox**. При наличии корня появится подтверждение замены. Редактирование под `STATION_GREYBOX_GENERATED` будет заменено, объекты вне него сохраняются. Операция поддерживает Undo. Не помещайте игрока внутрь генерируемого корня.
5. Генератор не добавляет игрока автоматически. Для проверки перетащите существующий `Assets/_Project/Prefabs/Player.prefab` в тестовую сцену, выделите его корень и выполните **Tools → Station → Move Selected Player To Spawn**. Сохраните сцену. Если используете персонажа из другой загруженной сцены, убедитесь, что он единственный активный игрок и камера; команда меняет его положение, но не переносит между сценами.
6. Нажмите Play. Управление остаётся существующим, из Input System проекта.

## Маршрут и двери

Начало снаружи → западный вход 01 → диспетчерская 02 → атриум 03. При закрытом G1 доступны 13 и 14 через C13/C14/C15, включая обратный путь. `Tools → Station → Toggle G1` открывает лабораторию 04. `Toggle G2` открывает сектор 05. Это переключатели коллайдеров-заглушек, без инвентаря и головоломок; их можно использовать во время Play Mode. Изменения в Play Mode не сохраняются.

В секторе 05 предложен маршрут: северный шлюз → западная зона наблюдения → восточная камера → южный проход → короткий спуск к заглушке уровня 2. Перегородки находятся в `PROPOSED_05_Partitions_ReviewInPlayMode` и требуют проверки удобства. Второй уровень не построен.

## Геометрия и принятые решения

- 15 комнат и 19 полигонов коридоров; стены и проёмы раздельные. Полы по настоящим контурам, включая вогнутости и диагонали.
- Пересекающиеся коридоры соединены без внутренних стен; общими границами с комнатами владеют стены комнат. Полы перекрывающихся коридоров могут совпадать по высоте — допустимо для этой итерации, возможен небольшой z-fighting.
- G1 перенесён из условной точки `(67,42)` в проём комнаты 04 на X=68, Z=42.75…45.25. В исходном месте перегородку можно обойти через C03b. G2 перекрывает дверной проём сектора 05.
- Высота обычных помещений 4.5 м, атриума 7 м, дверных проёмов 3 м, толщина стен 0.2 м. Потолки выключены: включайте дочерние объекты `Ceiling` вручную.
- Подход шириной 4 м с площадками на поворотах, необязательное наружное ответвление 3 м.
- Антресоль +3 м: пандус 9 м, ширина 2 м, ограждения. Техприямок −1.5 м: настоящий вырез 9×7 м, дно, подпорные стенки, ограждения и пандус 5 м. Спуск сектора 05 также имеет вырез в полу.
- Прямоугольники вертикальных участков и предложенные перегородки зафиксированы в коде по схеме v4. При переносе этих зон в JSON нужно согласованно изменить `Pit`, `Basement`, `Vertical` и `Restricted`; автоматическая адаптация этих деталей к произвольной новой планировке не реализована.
- Материалы и mesh-assets сохраняются рядом со сценой. Каждая генерация создаёт новую папку `Meshes_<id>`, чтобы старые сцены и Undo не теряли ссылки. Старые папки автоматически не удаляются.

## Игрок

Изменён только `Player.prefab`: Scale `(1,1,1)`, высота капсулы 2 м, радиус 0.32 м, Step Offset 0.3 м, Skin Width 0.04 м. Камера стоя остаётся на 1.7 м над подошвой. Камера в приседе исправлена до 0.85 м над подошвой (локальное Y −0.15 относительно центрального pivot). Ранее камера приседа была выше метровой капсулы.

В `Level1` уже был override масштаба Y=1; исходная сцена не переписывалась. Скорость, прыжок, наклоны, покачивание и код управления не менялись. Существующие overrides компонентов в других сценах могут перекрывать значения prefab.

## Проверка

Выполнено 15 ноября 2026: Unity завершил компиляцию и batch-проверку с кодом 0. После повторного открытия сохранённой сцены прошли 18 проверок маршрутов и 3 проверки пандусов (по 101 точке: наличие поверхности и свободное место для капсулы). Отчёт также приложен отдельно как `Validation.txt`. Полноценный проход от первого лица и интерактивное подтверждение повторной генерации пока не выполнены.

`Tools → Station → Validate Routes` проверяет доступность 01/02/13/14/04/05 из наружного spawn в трёх состояниях дверей. Используются коллайдеры Unity, капсула 2 м / радиус 0.32 м и сетка 0.5 м. Результат: `Assets/LevelDesign/Station/Greybox/Validation.txt` и Console. Проверка временно меняет состояния дверей и восстанавливает их.

Проверка рассчитана на изолированную тестовую сцену, не заменяет Play Mode: вручную проверьте присед, столкновения, движение по пандусам вверх/вниз, обзор с антресоли, спуск сектора 05, повторную генерацию с подтверждением и сохранение/повторное открытие сцены. В тестовой сцене нет автоматически созданного игрока.
